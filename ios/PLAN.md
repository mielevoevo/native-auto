# Phase 15: iOS port (planned 2026-11-16)

Native Swift + SwiftUI, written fresh with the Android app as the spec. The Android code (`app/`), `CLAUDE.md`,
`DECISIONS.md` and `Rider-Feedback.md` say what each feature does and why; port the behaviour, not the Kotlin line
by line. Pure logic is ported almost 1:1 together with its unit tests, so both apps compute the same figures.

**Versioning (rider, 2026-11-16):** the iOS line is its own: `MARKETING_VERSION` 0.1 at 15a, +0.1 per sub-phase,
1.0 when it matches the Android app. `CURRENT_PROJECT_VERSION` +1 per sub-phase build. Both in `ios/project.yml`.

**Setup:** free Apple ID, wired install from Xcode to the rider's iPhone 11 Pro Max (7-day installs). Deployment
target iOS 17. The Xcode project is generated by XcodeGen from `project.yml`; never commit `NativeAuto.xcodeproj`.

**Priority:** the port comes before the Android next update (rider, 2026-11-16).

## iOS limits (decided: port what the platform allows)

- **Media:** an app can't read or control another app's playback (Spotify etc.). Options: Apple Music only
  (`MPMusicPlayerController.systemMusicPlayer`), or the system route/volume controls without track info. Decide in 15e.
- **Calls:** no answering, declining or ending phone / WhatsApp calls. At most "a call is on" (CallKit's `CXCallObserver`).
- **Background:** guidance and trips while open, like Android. Background location would need "Always" permission.
- **Orientation:** per-app lock works; the rotation-lock-following AUTO mode needs checking.
- Screen stays on through `isIdleTimerDisabled` while the app is open.
